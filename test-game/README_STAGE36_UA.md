# Етап 36 — PlentyChess: контроль позиції та порівняння оцінок

Дата: 04.10.2026. Тестова гра v5.12.7-plenty-position-preview.
Основа — завершений етап 35; виправлення звітів Reckless збережено.

## Результат

Підключення PlentyChess тепер перевіряє повернуту рушієм позицію перед прийняттям ходу. Раніше перевірялася законність ходу, але не тотожність кореневої позиції рушія та гри. Збережена повна тестова копія, код і відтворювані результати. GitHub/чинний сайт не змінено.

Робоча оцінка залишається material-center-v1. Кандидат handcrafted-tapered-v1 не отримав достатніх доказів переваги й не підміняє базову збірку.

## Зміни гри

- Зіставляються повні FEN: розстановка, черга, рокіровки, en passant, лічильники та бюджет спеціальних ходів пішаків 10×10.
- Для подвійної цілі en passant допускається інший порядок клітин; некоректні позначення відхиляються.
- Перевіряються типи та узгодженість полів completed, terminal, depth, nodes, score, scorePerspective, move і PV. Перший хід PV повинен відповідати повернутому ходу, якщо PV є.
- За незавершеної першої ітерації дозволено легальний резервний хід без оцінки. Його не представляють як результат завершеного аналізу.
- В історію та експорт додається analysis.rootFen — позиція, яку підтвердив рушій.
- Невідповідна відповідь використовує наявний механізм паузи, зупинки годинника й повторної спроби. Непомітної підміни PlentyChess немає.
- Автоматична здача PlentyChess за сирим score залишається вимкненою. Матеріальні правила нічиєї не змінено.

Файли реалізації: game/index.html та game/game_plenty_adapter.js. WASM і worker рушія не змінені; нова компіляція для цієї правки не потрібна.

## Порівняння реальних WASM-збірок

32 партії: 2 розміри × 4 правила × 2 початкові послідовності × зміна кольору кандидата. Одна послідовність починається зі стартової позиції; друга — після симетричного розвитку коней і крайніх пішаків. По 40 мс на пошук, до 120 півходів пошуку на партію. Перевірка кожного ходу та кінцевого результату — правилами фактичної тестової гри. Обидва рушії відтворили кінцеві позиції всіх партій.

| Результат | Кількість |
|---|---:|
| Перемоги кандидата | 4 |
| Перемоги базової оцінки | 6 |
| Нічиї за правилами | 5 |
| Зупинено на ліміті; результат не визначений | 17 |
| Півходи, обрані рушіями | 3 233 |
| Додаткові задані дебютні півходи | 64 |

Ліміт ходів НЕ зараховано як нічию. П'ять нічиїх — повторення позиції. Матчі короткі, на одному середовищі й лише з двома початковими послідовностями. Бюджет у мілісекундах залежить від планувальника та навантаження. Це діагностичне порівняння, не Elo і не статистичний доказ переваги базової оцінки.

## Інші перевірки

| Перевірка | Підсумок |
|---|---|
| Реальний Plenty worker/WASM із поточною грою | Усі 8 конфігурацій; взяття A, FEN та експорт PASS |
| Некоректні відповіді | 11 випадків невідповідних полів; додатково формат en passant; відхилення PASS |
| Невідповідна позиція | Нуль виконаних ходів; годинник зупинений; справжній WASM успішно продовжив після повторної спроби |
| Мат/пат із лічильником 100 | 16 випадків; пріоритет мату/пату PASS |
| Самотній король | 8 конфігурацій продовжують гру без автоматичної поразки |
| Спеціальні випадки | Аварійна жертва, перетворення на 10-й горизонталі, подвійна ціль en passant, взяття C PASS |
| Тактичні тести | Обидва WASM: 84/84 законних ходів і завершена глибина 3 |
| Збіг із очікуваннями тактичних фікстур | Базова 84/84, кандидат 80/84 |
| Нативна фазова оцінка | 480 досяжних позицій; симетрія кольорів і файлів; оцінка не змінює дошку; пішаки, король-конь, A/C PASS |
| Нативний пошук із фазовою оцінкою | 89 запусків: дебюти, мат/пат, 50 ходів, повтори, аварійний вихід, PV, строки, скасування та TT PASS |

Чотири незбіги кандидата — вибір ходу турою замість очікуваного фікстурою взяття пішака. Самі фікстури не доводять, що альтернатива гірша. Це підстава для цільового дослідження, а не оголошення помилки оцінки.

## Відтворення

Node.js 20+, із кореня архіву:

```sh
node verification/stage36/test_adapter.cjs
node verification/stage36/test_special.cjs
node verification/stage36/tactics_wasm.cjs
node verification/stage36/compare_wasm.cjs
```

Нативно, g++ із C++17, із plenty-source/plenty-engine:

```sh
bash verification/test_core_eval.sh
POSITIONAL_EVAL=1 bash verification/test_core_search.sh
```

verification/stage36 містить партії ab_games.json, підсумок ab_summary.json, тактичні відповіді, інтеграційні звіти, журнали й патч. candidate містить отриманий CI-кандидат; game/plenty-run2-baseline — підключену базову збірку. plenty-source містить відповідні вихідні коди. Ліцензії збережено.

## Межі та продовження

Ці перевірки виконані в Node.js/worker_threads та нативно в C++; DOM для інтеграційних тестів змодельовано. Нової перевірки Chromium і Safari не було. Старі результати браузерних перевірок у stage33 належать попередній версії. Публікація та перевірка на справжньому iPhone ще попереду.

Наступний змістовний крок — розібрати характерні програші кандидата і внести одну ізольовану зміну оцінки, після чого повторити тактичні тести та розширене парне порівняння. Сумісної навченої NNUE для 10×8/10×10 поки немає; оригінальна мережа 8×8 не використовується. Калібрування 48 рівнів сили також залишається окремою роботою.
