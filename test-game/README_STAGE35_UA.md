# Етап 35 — виправлена звітність Reckless

Дата: 04.10.2026. Тестова гра v5.12.6-reckless-report-preview.
Початкова версія: збережений пакет етапу 34. GitHub і чинний сайт не змінено.

## Що зроблено

- Перевірений парсер підключено безпосередньо до game/reckless.worker.js.
- depth тепер належить тому самому рядку, що й оцінка та PV. completedDepth окремо зберігає завершену глибину пошуку.
- score.bound має exact, upperbound або lowerbound; scoreFromCompletedDepth показує, чи глибина оцінки не перевищує завершену.
- Парсер відкидає info string, додаткові multipv та рядки без оцінки. Для іншого обраного ходу відсутню оцінку не підставляє.
- Автоматична здача Reckless додатково вимагає exact, scoreFromCompletedDepth=true, узгоджених цілих глибин та trainingChoice=false. Збережені умови: лише свій король, від'ємна матова оцінка, глибина щонайменше 4, актуальні сторона/позиція/режим/покоління.
- Fairy-Stockfish також передає bound; автоматична здача відхиляє його оцінки-межі. Завершеність ітерації Fairy цим етапом не доведена й окремо не позначається.
- Нові поля потрапляють у запис ходу, експорт JSON і запис здачі. Старі записи без bound не вважаються достатніми для здачі.
- Оновлений параметр URL worker запобігає використанню старого worker за попередньою адресою.

Exact означає тип оцінки пошуку, а не математичний доказ мату. completedDepth — показник самого рушія. Політика здачі стала обережнішою, але таблиці всіх закінчень не побудовані.

У чотирьох незбігах фікстура очікувала взяття пішака, але рушій обрав хід турою. Це діагностичне спостереження, не доведена помилка: фікстури не є повними таблицями найкращих ходів. Тактичний набір не вимірює Elo, а потрібний для відтворюваного порівняння майбутніх кандидатів. Часові результати та кількість меж можуть змінюватися між запусками.

## Межі й наступний крок

WASM Reckless, його JS-завантажувач, WASM Fairy та оцінка позицій не змінені. Rust-компілятор у цьому середовищі відсутній; неперевірені зміни евристик до робочого рушія не додано. Наступний етап — окремий кандидат пріоритетів атак на A/C, перебудова та порівняння з baseline; потім окремо захист короля-коня. Перевагу кандидата слід перевіряти парними матчами зі зміною кольору.

Цього разу перевірено Node.js, VM із моделлю DOM та worker_threads з реальним WASM. Нового тесту Chromium/Safari не виконано: локального браузерного виконуваного файла немає. Старі браузерні результати в папках stage33 є історичними. Перед публікацією потрібна перевірка цієї версії в браузері та на iPhone. Правила автоматичних матеріальних нічиїх не змінювалися.

## Структура

- game/ — повна тестова копія; не завантажувати весь контрольний архів як корінь сайту.
- verification/stage35/ — нові тести, результати й reporting.patch.
- source/ — незмінний вихідний пакет базового Rust-рушія; змінений worker є відкритим JavaScript у game/ та в reporting.patch. Його ліцензія AGPL-3.0 збережена.
- Документи й результати stage33/stage34 — історичні. Цей README описує поточний стан.
